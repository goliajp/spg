## 2. 当前 SPG 实际行为(从代码反向 derive)

### 2.1 并发模型

`crates/spg-engine/src/lib.rs:355` 起的 TxState 结构:
- `tx_catalogs: BTreeMap<TxId, TxState>` — per-TX catalog 快照

STABILITY.md §1650 `Concurrency model (v6.9 series)` 描述:
> "single-writer / RwLock-reader concurrency model documented in the engine docs is frozen as-is for v6.x"
> "v6.9.0 bench measured throughput at the operating point SPG ships for"
> "v6.9.1 ship-rollup recorded the decision to **defer the bigger concurrency work to v7.x**"

→ **v7.x 期间并发模型没有"frozen"承诺**;v6.9.1 explicit defer 的 work 在 v7 期间是 expected to evolve。

### 2.2 实际 ANSI / Berenson-Adya 行为(experimentally needs to be measured)

从 single-writer + RwLock-reader 拓扑推:
- 读 / 写不冲突 — 多 reader 可见同一 snapshot;writer 独占
- 写 / 写串行(single-writer)→ **L0 lost update 不可能**
- 读 / 写之间(RwLock):writer 持锁时 reader 等;reader 看不到 mid-write 中间态 → **P1 dirty read 不可能**
- **P2 fuzzy read / unrepeatable read** — TBD,需要测;BEGIN 内多 SELECT 之间穿插一个 commit,第二个 SELECT 看不看到?
- **P3 phantom** — 同上,需要测
- **A5A read skew / A5B write skew** — single-writer 模型下应该都不可能,但需要测
- **PG SI G2-item allowance** — PG 在 Snapshot Isolation 下允许某些 anti-dependency cycles(Jepsen postgresql-12.3 fresh insert G2-item);SPG 是否复刻这个行为?TBD

## 4. v7.38 期间必须做的(plan §五 风险 3 闭合)

### 4.1 isolation 章节起草(进 STABILITY.md)

加 STABILITY.md 新章节 `## Isolation & concurrency contract` (位置:§31 Frozen surfaces 之后,v6.9 Concurrency model §1650 之前作 frozen 总章):

```markdown
## Isolation & concurrency contract (v7.38+)

SPG implements PostgreSQL-compatible isolation semantics within
the constraints of its single-writer / RwLock-reader concurrency
model. This contract is **frozen** from v7.38 forward; breaking
it requires a MAJOR bump.

### Default isolation level

`READ COMMITTED` — same as PG default. A new SELECT inside a
BEGIN block sees only data committed before that SELECT starts.

### Anomalies prevented

Notation: ANSI / Berenson-Adya phenomenon codes.

| Phenomenon | SPG behaviour | PG behaviour | Notes |
|---|---|---|---|
| P0 Dirty Write | **prevented** | prevented | single-writer model |
| P1 Dirty Read | **prevented** | prevented | reader can't see mid-write state |
| P2 Fuzzy Read | **prevented in default** | prevented in RR/SER, NOT in RC | TODO: verify; if SPG default actually
                                                                            prevents it, mention as "stronger than PG default" |
| P3 Phantom | **prevented** | prevented in SER, NOT in RC/RR | TBD: verify SPG behaviour |
| A5A Read Skew | TBD | varies by level | needs measurement |
| A5B Write Skew | TBD | depends on level | needs measurement |
| G2-item (Anti-dependency cycle on fresh insert) | **NOT prevented in default** | NOT prevented in PG SI | **SPG matches PG bug-for-bug to honor drop-in compat** |

### Anomalies SPG does NOT fix (intentional PG-parity)

- **G2-item on fresh insert under SI** — Jepsen postgresql-12.3
  reported PG allows this; we preserve the same allowance. Clients
  that depended on PG's actual behaviour continue to work. Adding
  the prevention would be a behaviour change for legitimate PG-port
  applications.

### `SET TRANSACTION ISOLATION LEVEL`

Parser-only support; the level requested is accepted but currently
mapped to SPG's default level. No-op upgrade for forward-compat;
no-op downgrade because SPG is stricter than `READ UNCOMMITTED` by
construction.

### v7.38 Hermitage acceptance

The v7.38 test constitution (`docs/TESTING.md` v2) requires the
above table be experimentally validated via Rust-port of
Hermitage 11 × 3 iso level matrix (33 cells). The matrix lives at
`xtests/isolation/hermitage/` and any change to the above table
must update both the matrix and STABILITY.md in the same commit.
```

## 5. 轴 4 isolation 测试 prerequisites(plan §二 轴 4 列出的 deliverable)

### 5.1 spec 格式支持

PG `src/test/isolation` 用 `.spec` 文件:
```
setup { CREATE TABLE accounts(...); INSERT INTO accounts ...; }
teardown { DROP TABLE accounts; }
session "s1" {
  setup { BEGIN ISOLATION LEVEL READ COMMITTED; }
  step "s1u" { UPDATE accounts SET bal = 100 WHERE id = 1; }
  step "s1c" { COMMIT; }
  teardown {}
}
session "s2" { ... }
permutation "s1u" "s2u" "s1c" "s2c"
```

SPG 需要:
1. **Rust 版 isolationtester** parsing 这个格式 — 进 `xtests/isolation/runner/`
2. **lock view 等价物** — 探测 step 在等 lock 时 isolationtester 应能识别;PG 用 `pg_locks`;SPG 需要暴露等价 view(`spg_blocking_pids` 或 catalog table)
3. **`SET TRANSACTION ISOLATION LEVEL`** — 至少 parser 接受,语义上 NO-OP map 到 default 也行(per §4.1)

### 5.2 Hermitage 11 case 矩阵

PG `src/test/isolation/specs/` 已有 ~30 个 spec 文件,但 Hermitage(Martin Kleppmann)是更系统的覆盖:11 个 testcase × 3 个 ISO level = 33 cell。

每 cell 输出二选一:`防` / `不防`,跟期望对比:

| Hermitage testcase | RC 期望 | RR 期望 | SER 期望 |
|---|---|---|---|
| G0 (write cycle) | 防 | 防 | 防 |
| G1a (aborted reads) | 防 | 防 | 防 |
| G1b (intermediate reads) | 防 | 防 | 防 |
| G1c (circular info flow) | 防 | 防 | 防 |
| OTV (observed tx vanishes) | 防 | 防 | 防 |
| PMP (predicate-many-preceders) | 不防 | 防 | 防 |
| LU (lost update) | **不防** | 防 | 防 |
| RA (read skew) | 不防 | 防 | 防 |
| WS (write skew) | 不防 | 不防 | 防 |
| G2-item | 不防 | 不防 | 防 |
| G2 (anti-dep cycle) | 不防 | 不防 | 防 |

SPG default = `READ COMMITTED` → 期望符合该列。
**任何 mismatch 进 STABILITY.md `Anomalies prevented` 表的 "Notes" 列说明**。
