## 1. 目标 / 约束

### 必须达到
1. **任何 perf gate fail → 自动产 decomposition skeleton 到 `.claude/notes/perf-decomp/<branch>-<shape>-<date>.md`**
2. **Skeleton 必须 fill 才能 merge** — PR merge gate 检查 skeleton 路径存在且非空
3. **候选 file:line 自动检测** — 基于 git diff 找近期改的 hot path,预填进 skeleton "Attack 候选" 列
4. **触发词 lint 误报防护** — `docs/PERF_METHODOLOGY_VS_FOSS.md` §4 触发词清单接进 CI,但讨论 vs hand-wave 要能区分
5. **零负担 dev-cycle** — 本地 `cargo test` / `bench` 不触发 CI 工作流(只在 `gh pr` 触发)
6. **fast tier 不破预算** — skeleton 生成 + lint 是 millisecond 级,不影响 fast 5min 上限

### 不允许的形态
- ✗ "perf fail 时让开发者自己手写 decomposition" — 实证 SPG SCALARSQ 浪费 10+ 轮,自动化是 hard requirement
- ✗ 触发词命中即 fail — 会误杀讨论"为什么不是 architectural ceiling" 这种正当反思
- ✗ skeleton 用 binary stored format(json / sqlite) — markdown 才允许 PR review 人读
- ✗ 触发条件用 magic string — 用明确 perf gate failure 信号(exit code + stderr marker)

## 2. 触发条件 — when 产 decomposition skeleton

### 2.1 三个明确触发点

| 触发点 | 检测方式 | 触发产物 |
|---|---|---|
| **A. perf gate fail** | `cargo test perf_gate*` 退出非零 + stderr 含 `PERF_GATE_FAIL` marker | `.claude/notes/perf-decomp/<branch>-<shape>-<date>.md` |
| **B. v7.37.4 baseline 退化 > 5%** | `xtests/perf_gate/baseline_lock_v7_37_4.rs` 跟 `TESTING_V2_SKELETON.md` 锁的 13-shape 表对照 | 同上,`<shape>` 是退化的 endpoint |
| **C. PR description / commit message 含触发词** | CI lint scan `git log -1` + PR body | 自动 review-block,要求 skeleton 链接 |

### 2.2 不允许的"模糊"触发

- ✗ "commit message 含 `perf` 关键字" — 太宽,`docs: fix perf typo` 也会命中
- ✗ "改动 hot path 文件" — 没法静态判定;v7.38 plan §一一 由 perf gate fail 反向触发,更可靠

### 3.4 候选 file:line 自动检测

```rust
// xtests/perf-skeleton-gen/src/detect_hot_path.rs

pub fn detect_candidates(branch: &str, base: &str) -> Vec<Candidate> {
    let diff = Command::new("git")
        .args(["diff", "--stat", "--name-only", &format!("{base}...{branch}")])
        .output()
        .expect("git diff");
    let files: Vec<PathBuf> = String::from_utf8_lossy(&diff.stdout)
        .lines()
        .map(PathBuf::from)
        .collect();

    files.into_iter()
        .filter(|p| p.extension() == Some("rs".as_ref()))
        .filter_map(|p| {
            let lines_changed = git_lines_changed(&p, branch, base);
            // Heuristic: hot-path likelihood from file name + function-density
            let is_hot = is_hot_path_file(&p);
            if is_hot && lines_changed > 0 {
                Some(Candidate {
                    path: p,
                    lines_changed,
                    contains: nearby_function_signatures(&p),
                })
            } else { None }
        })
        .collect()
}

/// Heuristic table — hot-path files (curated by us, not heuristic-derived).
/// Maintained as code; update when adding hot crates.
fn is_hot_path_file(p: &Path) -> bool {
    const HOT_PATTERNS: &[&str] = &[
        "crates/spg-engine/src/aggregate.rs",
        "crates/spg-engine/src/select.rs",
        "crates/spg-engine/src/joinfold.rs",
        "crates/spg-engine/src/subquery.rs",
        "crates/spg-engine/src/scalarsq_streaming.rs",
        "crates/spg-engine/src/eval/",          // dir match
        "crates/spg-engine/src/expr_analysis.rs",
        "crates/spg-storage/src/persistent_btree.rs",
        "crates/spg-storage/src/persistent.rs",
        "crates/spg-storage/src/codec.rs",
        "crates/spg-sqlx/src/pool.rs",
        "crates/spg-server/src/wire.rs",        // 假设 pgwire 入口
    ];
    let s = p.to_string_lossy();
    HOT_PATTERNS.iter().any(|pat| s.contains(pat))
}
```

**Note**:Heuristic 不试图"猜对所有 hot path",只是给 decomposition 起步**预填提示**。
真正 attack 时 decomposer 必须读 PG / FOSS source 做 ground truth(见 doctrine §2 Phase A)。

## 4. Merge gate — skeleton 必须 fill

### 4.1 PR check 检测逻辑

```yaml
# .github/workflows/perf-decomp-required.yml (新加 workflow)
name: perf-decomp-required
on:
  pull_request:
    types: [opened, synchronize, labeled, unlabeled]

jobs:
  check-decomp:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }

      - name: Check if PR has needs-decomp label
        id: label
        run: |
          if gh pr view ${{ github.event.pull_request.number }} --json labels --jq '.labels[].name' | grep -q '^needs-decomp$'; then
            echo "label_present=true" >> $GITHUB_OUTPUT
          else
            echo "label_present=false" >> $GITHUB_OUTPUT
          fi

      - name: Find decomp notes for this branch
        if: steps.label.outputs.label_present == 'true'
        run: |
          BRANCH="${{ github.head_ref }}"
          NOTES=$(find .claude/notes/perf-decomp -name "${BRANCH}-*.md" 2>/dev/null)
          if [ -z "$NOTES" ]; then
            echo "::error::PR labeled needs-decomp but no decomp note found at .claude/notes/perf-decomp/${BRANCH}-*.md"
            exit 1
          fi

          # Check each note for completion
          for f in $NOTES; do
            # The skeleton ships with "TODO" everywhere; a filled one shouldn't have
            # >5 raw "TODO" tokens remaining.
            TODO_COUNT=$(grep -c "TODO" "$f" || true)
            if [ "$TODO_COUNT" -gt 5 ]; then
              echo "::error::Decomp note $f still has $TODO_COUNT TODO entries; must fill."
              exit 1
            fi

            # Check ±20% budget validation present
            if ! grep -q "Total budget validation" "$f"; then
              echo "::error::Decomp note $f missing budget validation"; exit 1
            fi

            # Check Top-N actionable attacks has at least one filled row
            if ! grep -A1 "^| 1 |" "$f" | grep -v "TODO" >/dev/null; then
              echo "::error::Decomp note $f Top-N attacks table has no filled rows"; exit 1
            fi
          done
```

### 4.2 标签自动管理

- perf-skeleton-gen 生成 skeleton 时,通过 `gh pr edit --add-label needs-decomp`
- merge gate enforce 在 `needs-decomp` 标签存在时 skeleton 必须 fill
- 开发者填完后 PR description 加 `Closes-decomp: .claude/notes/perf-decomp/...md`,CI 删 label

## 5. 触发词 lint — 误报防护

### 5.1 设计:三档命中

| 命中位置 | 行为 |
|---|---|
| **PR description (top)** | strict — 命中 = fail |
| **PR description (`<details>` quote block)** | tolerant — 命中 = warn,允许讨论 |
| **commit message** | strict — 命中 = fail |
| **ack note(`spg-*-ack-*.md`)** | strict — 命中 = fail |
| **decomp note 内** | tolerant — 命中 = warn(它本身就是反思,要 quote 触发词) |
| **markdown code block (```...```)** | exempt — 引述 / 示例,不 fail |

### 5.2 触发词清单(借 `docs/PERF_METHODOLOGY_VS_FOSS.md` §4)

```rust
// xtests/lint-perf-acceptance/src/triggers.rs

pub const BANNED_PHRASES: &[BannedPhrase] = &[
    BannedPhrase {
        pattern: r"architectural ceiling",
        replacement_hint: "I haven't decomposed deeply enough. Show me 18-stage breakdown.",
    },
    BannedPhrase {
        pattern: r"(?i)language ceiling",
        replacement_hint: "Which abstraction is wasting CPU? Identify it.",
    },
    BannedPhrase {
        pattern: r"(?i)language(\s+)idiomatic.*(slower|gap|diff)",
        replacement_hint: "C/Rust idiomatic gap ≤ 1.5×. Anything more is abstraction waste.",
    },
    BannedPhrase {
        pattern: r"user-?space (not |un)touchable",
        replacement_hint: "Read the competitor's user-space code. How do they do it?",
    },
    BannedPhrase {
        pattern: r"sub-?(bench |benchmark )?noise",
        replacement_hint: "Tighten variance band (n=99→n=1000) or stack 5 sub-noise wins.",
    },
    BannedPhrase {
        pattern: r"structural gap",
        replacement_hint: "What structure exactly? file:line please.",
    },
    BannedPhrase {
        pattern: r"noise band within variance",
        replacement_hint: "Tighten variance band, don't obscure with it.",
    },
    BannedPhrase {
        pattern: r"主要场景赢|绝大部分赢|绝大多数赢|大体上.*[赢胜]",
        replacement_hint: "List every losing endpoint. Decompose each.",
    },
    BannedPhrase {
        pattern: r"客户可以接受.*[输输]|客户.*容忍",
        replacement_hint: "Our standard is higher than the customer's. Decompose.",
    },
    BannedPhrase {
        pattern: r"TCP loopback (overhead|residual)|kernel.*(残余|residual)",
        replacement_hint: "Competitor faces same loopback. How do they save µs?",
    },
];

pub struct BannedPhrase {
    pub pattern: &'static str,
    pub replacement_hint: &'static str,
}
```

### 5.3 Lint runner

```rust
// xtests/lint-perf-acceptance/src/main.rs

fn lint_file(path: &Path, strict: bool) -> Vec<Violation> {
    let content = fs::read_to_string(path).unwrap_or_default();
    let mut violations = Vec::new();

    // Strip out exempt regions: ``` code blocks ```
    let stripped = strip_code_blocks(&content);

    // Strip out tolerant regions: <details>...</details> if strict mode
    let target = if strict {
        strip_details_blocks(&stripped)
    } else {
        stripped
    };

    for banned in BANNED_PHRASES {
        let re = regex::Regex::new(banned.pattern).unwrap();
        for m in re.find_iter(&target) {
            violations.push(Violation {
                path: path.to_path_buf(),
                phrase: m.as_str().to_string(),
                hint: banned.replacement_hint.to_string(),
                strict,
            });
        }
    }
    violations
}
```

### 5.4 CI 接进

```yaml
# .github/workflows/perf-acceptance-lint.yml
name: perf-acceptance-lint
on: [pull_request]
jobs:
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }

      - name: Lint PR description
        run: |
          gh pr view ${{ github.event.pull_request.number }} --json body --jq '.body' > /tmp/pr-body.md
          cargo run -p lint-perf-acceptance --release -- /tmp/pr-body.md --strict

      - name: Lint commit messages (only this PR's commits)
        run: |
          BASE_SHA=$(gh pr view ${{ github.event.pull_request.number }} --json baseRefOid --jq '.baseRefOid')
          git log --format=%B "${BASE_SHA}..HEAD" > /tmp/commits.md
          cargo run -p lint-perf-acceptance --release -- /tmp/commits.md --strict

      - name: Lint changed ack / decomp notes
        run: |
          for f in $(git diff --name-only origin/${{ github.base_ref }} HEAD | grep -E '(spg-.*-ack-|perf-decomp).*\.md$'); do
            STRICT_FLAG=""
            if echo "$f" | grep -q 'spg-.*-ack-'; then STRICT_FLAG="--strict"; fi
            # decomp notes use tolerant mode (--strict omitted)
            cargo run -p lint-perf-acceptance --release -- "$f" $STRICT_FLAG
          done
```

```rust
// xtests/lint-perf-acceptance/tests/triggers.rs

#[test]
fn ack_strict_mode_catches_architectural_ceiling() {
    let v = lint_text("This is an architectural ceiling we can't break.", Strict::Yes);
    assert_eq!(v.len(), 1);
}

#[test]
fn decomp_tolerant_mode_allows_phrase_in_discussion() {
    // decomp notes legitimately discuss banned phrases as reflection.
    let v = lint_text(
        "Earlier ack claimed 'architectural ceiling' — this was wrong; \
         decomposition revealed catalog::get BTreeMap descent.",
        Strict::No,
    );
    assert_eq!(v.len(), 0, "decomp tolerant mode should allow quoted reflection");
}

#[test]
fn code_block_quote_is_exempt_in_strict_mode() {
    let v = lint_text(
        "```\n> claim: architectural ceiling\n> response: 18-stage decomp showed otherwise\n```",
        Strict::Yes,
    );
    assert_eq!(v.len(), 0, "code-block quoted reflection should be exempt");
}

#[test]
fn details_block_tolerant_in_strict_mode() {
    let v = lint_text(
        "<details>\nThe customer asked about architectural ceiling concerns.\n</details>",
        Strict::Yes,
    );
    assert_eq!(v.len(), 0, "<details> block is exempt even in strict mode");
}
```
