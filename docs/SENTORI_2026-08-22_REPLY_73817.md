## 1. Under MySQL, trailing spaces stopped counting

`'alpha'` and `'alpha  '` were the same value to a comparison, a
`DISTINCT`, a `GROUP BY` and an `IN` list. Measured against MySQL 9.7.2
at its default collation:

| | MySQL 9.7.2 | SPG before |
|---|---|---|
| `WHERE s = 'alpha'` | 1 | 1,2 |
| `s IN ('alpha','beta')` | 1,3,4 | 1,2,3,4 |
| `COUNT(DISTINCT s)` | 3 | 2 |
| `GROUP BY s` groups | 3 | 2 |

Worse, `SELECT DISTINCT s` and `count(DISTINCT s)` disagreed with each
other in the same session.

The cause is worth stating exactly, because it was not carelessness. The
function that decided this had a comment saying where its rule came
from: *"measured on MariaDB 11"*. MariaDB's default collation is PAD
SPACE and that measurement was correct — about MariaDB. We advertise
`8.0.0-spg-v…` on the MySQL wire, and MySQL 8.0's default is NO PAD. The
rule had been calibrated against the engine we do not claim to be.

Eight of eight cases now match MySQL, and the three paths agree with one
another. `CHAR(n)` keeps its old answer for a stated reason: a CHAR's
trailing spaces are padding, a property of the type, and both engines
ignore them.

## 2. Why we did not catch it, which is the larger story

Our corpus has a `mysql/` directory. The runner that executes it had no
notion of a SQL dialect at all, so every file in it had been running in
**PostgreSQL** dialect since the day it was created.

We found five more of the same shape while fixing that one, and three of
them were in the tools built to catch it:

- the first instrument we wrote for this read the file's *declaration*
  instead of asking the engine, so it reported the wrong mode too;
- our own written plan called a line in a wish-list comment a
  capability;
- a registry whose header promises *"CI lint rejects any symbol that
  does not appear below"* — with nothing reading the file;
- the gate step named "opens the previous release's data directory" had
  the directory name typed in as a literal, so every release captured a
  fixture nothing opened;
- and the three-engine differential (below) had never put SPG into
  MySQL's mode at all.

Every one of these is the same failure: a name is a claim, and nothing
was checking it. Each now has a mechanical check that goes red, not a
note.

## 3. The three-engine differential now gates a release

We run a differential against live PostgreSQL 18, MySQL and MariaDB. It
was in a tier nothing schedules, so it had never blocked a release; and
it ran SPG in PostgreSQL dialect on all three legs, so its MySQL and
MariaDB comparisons were not comparing what their names said.

Both are fixed, and it runs in the release gate now — measured at 101
seconds for all three legs.

We also added a fixture that declares its own collation, because our
oracle containers are pinned to a byte-wise one and no fixture could see
collation behaviour at all. It immediately found a gap we have **not**
closed: the pad attribute belongs to the collation *name*, and both
engines agree on the mapping —

| | | `COUNT(DISTINCT)` | `WHERE = 'alpha'` |
|---|---|---|---|
| `utf8mb4_0900_ai_ci` | NO PAD | 3 | 1 |
| `utf8mb4_bin` | PAD SPACE | 3 | 2 |
| `utf8mb4_general_ci` | PAD SPACE | 2 | 2 |

SPG answers the first row correctly and the other two wrongly. That is
recorded as an expected-failure lock in the harness rather than left out
of the corpus: it is visible on every run, it fails the moment it moves,
and deleting the lock is what closing it will look like.

## 4. The acceptance panel speaks MySQL

Our drop-in acceptance harness checks that a customer's schema and
queries land on an SPG image. It probed one of the three engines we
claim to drop in for. It now opens the MySQL wire on the container and
asks a MySQL client the questions the last two releases were about.

Its own negative control: run against the **published 7.38.16** image it
fails four of seven; against 7.38.17 it is seven of seven.

## 5. A tier report that cannot overstate

Ten of our test steps are in a tier nothing schedules. A green release
gate therefore read as "everything green" and was not. The summary now
ends with a line naming exactly what did not run, and a script exists to
run that tier nightly — we have not installed a scheduled job on anyone's
machine, that is the machine owner's call.

## Still open, named rather than left out

- **Pad-by-collation-name**, above. `utf8mb4_bin` and
  `utf8mb4_general_ci` give the wrong answer for trailing spaces.
- **A cross-type comparison across tables.** Under MySQL, `a.c = b.s`
  where one side is `CHAR` and the other `TEXT` evaluates false, and a
  join built on it returns no rows. Same-type comparisons are correct
  and PostgreSQL sessions are unaffected. Found while measuring the
  above; localised, not yet fixed.
- **A MariaDB acceptance panel.** The two engines disagree about
  trailing spaces, so it needs its own expectations rather than a second
  name for the MySQL ones.
- **MySQL warning diagnostics** (`SHOW WARNINGS`, `@@warning_count`),
  carried over.
